# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, architecture, and sharp-edge notes that should travel with the code.

- [VISION.md](VISION.md) is the project's acceptance policy: accuracy first, report and let the caller decide, delegate never reimplement, absent data stays absent, never root, tests never run a real updater. Check a proposed change against it before building.
- The approved spec is GitHub issue https://github.com/andrewesweet/upkeep-axi/issues/1 (label ready-for-agent); it owns the two-verb contract (`status` read-only, `apply` plan-by-default with `--execute`), the surface list, and the out-of-scope list. Every version-one surface, including the Firstmate fork sync, is built.
- `upkeep-axi` runs on this WSL2 Ubuntu host only in version one, and never as root (`assertNotRoot` in `src/exec.ts` gates every command).
- One module per surface in `src/surfaces/`, each exposing `detect`, `status`, and `apply` (the contract in `src/types.ts`). `apply` declares the fixed delegate argv - the vendor's own updater, spelled once per module, never assembled elsewhere; `applyCommandText` in `src/surfaces/shared.ts` is the single spelling used by status rows, plan output, and journal records. There is no `pin` method: pin text lives on each row as `pinCommand`. apt's `apply` returns undefined (report-only) and naming apt for apply is a usage error.
- Apply (`src/apply.ts`, wired in `src/cli.ts`): plans from the same rows `status` produces; `--all` requires `--tier patch|minor|major` and takes every known gap at or below the tier; a named surface takes every known gap (`--tier` is only valid with `--all`); named tools are selected exactly (whatever their tier) and are the only rows a tool-named selection plans. A row may carry `refusal` - the reason no delegate exists that the surface knows (firstmate conflicts) - reported in the skipped block wherever the caller asked for it. Execution (`--execute`) runs each delegate through one runner (`runDelegate` in `src/exec.ts`): nonzero exit or spawn failure is a refusal reported verbatim and never retried; a delegate still running at its budget (per-surface `applyTimeoutMs`, default 900000) is unref'd - never killed mid-write - and reported `unconfirmed`. Refused and unconfirmed rows carry the delegate's output verbatim in the report's sparse `output[]` block, displayed capped at 800 characters with a `… (truncated, N chars total)` marker (`truncateOutputDetail` in `src/render.ts`); `apply --full` lifts the display cap only. An `--execute` run where any `results[]` row is refused or unconfirmed sets exit 1 (captain's ruling) with every row's outcome still on stdout; an all-applied or empty `results[]` exits 0. An empty plan renders an explicit `Nothing to apply: ...` state and exits 0. Executed reports carry a sparse `summary` of counts by outcome. Execution goes surface by surface: after a surface's delegates ran it is re-probed and its records journaled before the next surface starts; applied rows (delegate exit 0) record `after`, so a delegate that exited 0 without changing the version shows `after` equal to `before`; refused/unconfirmed rows keep `after` absent. In-use refusal outranks tier: an in-use row is refused with the reason even without a latest.
- In-use detection (`src/inuse.ts`) reads exactly three sources: `herdr agent list` (inactive statuses done/stopped/exited/dead), `no-mistakes runs` (active running/fixing rows drive the agent list in `NO_MISTAKES_DRIVEN`), and the process table via `/proc/<pid>/exe` (excluding our own ancestor chain, matching only copies on this run's PATH, plus any directory prefix a row declares in `executableRoots` - a bundle's processes run under `<root>/`, e.g. the snap surface's `/snap/<name>/`, where the launcher symlink on PATH cannot see them; one process matched both ways is one fact). Never Firstmate's files. A surface module may declare `replacedExecutables(row)` - npm rows carry their `bin` names from `npm ls -g --json --long`, so a package is in use through the executables it installs (a package with no bin is never in use); a missing source contributes nothing. Rows keep `in_use` absent unless installed with an apply command.
- The journal (`src/journal.ts`) is append-only JSONL at `$XDG_STATE_HOME/upkeep-axi/journal.jsonl` (default `~/.local/state`), one record per tool per apply with `surface,tool,before,after,tier,command,exit,duration_ms,pin,started_at` plus `id` = the line number it was appended at. Every executed apply journals, refusals included. `upkeep-axi journal` prints it (TOON/--json). `status --since <cursor>` (record id or ISO timestamp) reports rows whose installed version differs from the `before` of their first record strictly after the cursor (a refused apply changes nothing and is not reported); `--changed-only` reports rows whose installed version differs from the journal's newest record of them (`after`, else `before`; an empty journal is no baseline and reports everything). Given both, `--since` decides. The per-surface `applyTimeoutMs` config option exists so tests can exercise the unconfirmed path with a short budget.
- Registry surfaces stay in declaration order (`SURFACE_REGISTRY` in `src/surfaces/index.ts`): npm, mise, uv, cargo, bun, gh, skills, fnm, apt, claude, codex, opencode, pi, herdr, no-mistakes, firstmate. Status output keeps that order and is never sorted. Adding a surface is one module plus one registry entry; config only toggles or parameterizes what is there.
- Version probes per surface: npm `ls -g --json --long` + `view <pkg> version`; mise `ls --json` + `outdated --json` (only tools with updates appear there - absence means latest stays absent, never "current"; several installed versions collapse to one row, the active installed one - a requested-but-missing version never hides an installed one - and pins use `mise use -g`); uv `tool list` + `tool list --outdated` (same only-outdated semantics; uv's `- bin` lines are skipped and the `v` prefix is required when parsing); cargo `install --list` + `search <crate> --limit 1`; bun `pm ls -g` + `pm view <pkg> version`; gh `--version` + `extension list`, latest only via `extension upgrade --all --dry-run` (only extensions it would upgrade appear; pinned extensions carry no apply command; gh itself has no self-update check); skills `list -g` (or `npx -y skills`) with no update check exposed - installed only; fnm `list` (collapses to the default-alias version, else the last installed) + `ls-remote --lts` (highest listed), apply names `fnm install && fnm default` and is only published with a concrete latest and a tier other than none (never a downgrade); apt `list --upgradable` parsed with the exact `sudo apt-get update && sudo apt-get upgrade` apply text - report-only, plus a `reboot-required` row whose path is the `rebootRequiredPath` surface option (default /var/run/reboot-required). Debian versions tier by epoch, then numeric prefix, so revision-only bumps can tier none; the row still carries both versions verbatim; claude `--version` + Claude state files under `$CLAUDE_CONFIG_DIR` (default `~/.claude`): enabled plugins from settings.json, install facts and versions from plugins/installed_plugins.json (unreadable record: no plugin rows), marketplaces from plugins/known_marketplaces.json; codex `--version` + `npm view @openai/codex version` (apply is `codex update`, the standalone installer has no pin); opencode `--version` (pin via `opencode upgrade <version>`); pi `--version` + `pi list` (sources only, never versions; two-space indent is a package, four-space is a skipped path line); herdr `--version` + `$XDG_CONFIG_HOME/herdr/plugins.json` (plugin ids and versions; plugins have no apply - herdr has no plugin updater - while herdr itself delegates to `herdr update`); no-mistakes `--version` (delegate `no-mistakes update`, refusal reported verbatim); firstmate (next entry). claude, opencode, pi, and no-mistakes announce their own updates, so their latest/tier stay absent unless a config entry wires the announcement probe. mise itself reports `mise self-update`; the uv binary belongs to whichever surface manages it (mise on this host).
- The firstmate fork surface (`src/surfaces/firstmate.ts`) reads the local clone (`clonePath`, default /home/andre/tools/firstmate - a surface option, not a per-tool `git` entry; remotes `upstream`/`origin` and branch `main` are fixed): fetch both remotes, count each side ahead on the default branch, and when diverged classify by a trial rebase of the fork's bespoke commits onto upstream main in a scratch worktree under `$XDG_STATE_HOME/upkeep-axi/firstmate-sync/` (trial- mkdtemp, discarded in a finally). Classes: current (equal, or fork ahead with nothing new upstream), fast-forward (nothing bespoke), clean-rebase, conflicts (files listed on `row.sync`). version = fork main sha, latest = upstream main sha, tier = major for rebase/conflicts, minor for fast-forward, none for current. Apply never touches the clone or fork main: fast-forward pushes `<upstreamSha>:refs/heads/sync/upstream-<sha7>` to the fork and opens a plain `gh pr create` (body states pure fast-forward; needs the fork remote to parse as a GitHub slug - a non-GitHub fork remote is a fact, not an error, and only drops this path); clean-rebase runs four git steps (worktree add --detach `apply-<sha7>`, rebase, `push no-mistakes HEAD:refs/heads/sync/rebase-<sha7>`, worktree remove) - the branch name is the gate run's identity, and an interrupted run leaves the scratch for a crew task; conflicts set `row.refusal` and refuse at plan time (nothing runs, nothing journaled). pin = `git -C <clone> push --force origin <forkSha>:refs/heads/main` (the pre-sync fork main commit; the history rewrite stays the captain's act). `replacedExecutables` is `[]`: the apply replaces no executable, so the row is never in use.
- Semver tiers live in `src/semver.ts` and have one implementation: equal parsed parts or an installed version newer than latest are `none`, both parse with latest newer decide patch/minor/major, a gap with an unparseable side is `major`, and an unknown version yields no tier at all. `extractVersion` is a documented heuristic over free-form `--version` output.
- PATH skew is measured in `probePathSkew` (`src/surfaces/shared.ts`): every copy of the command on PATH is asked its version; skew is reported only when the resolved copy parses older than a later copy. Config-driven probes (skew, announcement) run only for installed rows; a configured entry the manager does not know reports `installed=false` with no version, apply, or pin.
- Config is tool-owned: `--config <path>` or `$XDG_CONFIG_HOME/upkeep-axi/config.json` (default `~/.config/upkeep-axi/config.json`). Per-tool entries use Firstmate's watched-tools field names (`name`, `command`, `version_args`, `announce_pattern`, `announce_args`, `git`); `git` is accepted for schema compatibility only - the firstmate surface takes surface-level options instead. A malformed config, including an unknown surface id, is a usage error, never ignored.
- Probe failures report verbatim in the sparse `errors` block; the manager row stays with whatever facts survived. Failed latest-version probes keep `latest` and `tier` absent (per-row absence, not a surface error).
- Output contract: default TOON with `bin`/`description`/`generatedAt`/`schemaVersion` (3), a `tools[]` row per tool (`surface,tool,installed,version,latest,tier,in_use,apply,pin`), sparse `errors[]`/`skew[]`/`announce[]`/`in_use[]`/`sync[]` blocks joined on surface+tool, a `summary` block (counts: tools, known gaps by tier, in_use, skew - zero facts stay absent), and a `help[]` block; `--json` emits the same model. Status `help[]` is derived from the invocation and rows (`statusHelpHints` in `src/render.ts`): the scoping hint only when unscoped, the apply hint only when known gaps exist that apply can plan - never for apt, whose scoped gaps hint the row's own `sudo apt-get` text and whose apt-only gaps drop the hint. `--fields <a,b,c>` (status and journal) projects rows to a validated subset of the row model in the caller's order, shared by TOON and JSON; unknown fields are usage errors; `status` refuses stray positionals. `sync[]` carries the firstmate fork facts (class, counts, fork slug, conflict files). Renderers live in `src/render.ts`; field spellings never differ between TOON and JSON.
- Tests spawn the built CLI (`dist/bin/upkeep-axi.js`) with an environment whose PATH contains only the test's fake executables - never the parent env - so no test can reach a real package manager. Fakes must use shell builtins only (`echo`/`case`/`test`/`read`/arithmetic), because `cat`/`printf`/`sleep` are not on that PATH; a test that needs a slow delegate busy-waits with a counter loop. The npm fake mutates `$HOME/.npm-state` so an apply is observable end to end; the journal is pointed at the test's `XDG_STATE_HOME`. The firstmate tests (`test/firstmate.test.ts`) build real fixture repositories (bare upstream/fork/gate + a working clone, all local-path remotes, no network); their `git` fake is a shim that forwards to the real binary (resolved once via `command -v git`) and answers `remote get-url origin` with the real fork's GitHub URL; the gate fixture's post-receive hook echoes the words the real gate prints, so applied output is observable. The one opt-in live smoke of real `status` is behind an environment flag (UPKEEP_AXI_LIVE_SMOKE=1), never part of the suite's default run.
- Plumbing (routing, `--help`, error framing, exit codes: 0 success, 1 error, 2 usage) comes from `axi-sdk-js` `runAxiCli`; errors print to stdout with an `error:` prefix. `bin/upkeep-axi.ts` answers bare `-v`/`-V`/`--version` through `axi-sdk-js/fast-path` plus the leaf `src/version.ts` so the command graph never loads on that path. The CLI wires `status` (the default command), `apply`, `journal`, `setup`, and `ambient`; the SDK's built-in `update` is shadowed with a refusal because the tool is not published to npm.
- Ambient context (AXI §7; the ten principles live in the committed `.agents/skills/axi/SKILL.md`): `setup hooks` wraps the SDK's `installSessionStartHooks` with marker `upkeep-axi`; the SDK's hook commands carry no arguments, so the bounded dashboard lives behind the sibling entrypoint `dist/bin/upkeep-axi-ambient.ts` (runs `main({ argv: ["ambient"] })`) that setup installs as the hook command. `ambient` (src/ambient.ts) never probes: it reads the snapshot every unfiltered `status` run writes to `$XDG_STATE_HOME/upkeep-axi/status.json` (`src/snapshot.ts`; a `--surface` run never writes it), overlays journal records started after the snapshot (an `after` replaces the row's version and re-tiers it against the snapshot's latest), and shows only gaps and in-use rows, in-use first then tier then registry order, capped at `AMBIENT_MAX_ROWS` with the overflow named in `help[]`; no snapshot is a definitive empty state naming `status`, and a snapshot a day or older adds `snapshotAgeDays` and a refresh hint. The `ambient:` summary string is identical in TOON and JSON. The hook keeps the SDK's default 10 s budget because the dashboard does no work that could outrun it. The skill (`skills/upkeep-axi/SKILL.md`) is generated from the same `TOP_HELP`/`DESCRIPTION` constants by `scripts/build-skill.ts` (quota-axi pattern); CI runs `build:skill -- --check`, so regenerate after changing TOP_HELP. Hook tests point the SDK's `homedir()` at the fixture via the spawned env's `HOME`; the claude-surface fixtures already own `.claude/settings.json`, so hook tests assert on content, not file existence.
